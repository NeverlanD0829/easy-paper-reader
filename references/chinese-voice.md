# 中文研究员口吻规范

这一条规范管的是**怎么说**，不管说什么。`audit_article.py` 查内容是否齐全，
`check_tone.py` 查口吻是否像人写的，两道门都要过。

判定标准只有一条：**一个认真写字的研究员会不会故意这么写**。会，就留着；
只是因为顺手、因为模板、因为显得整齐才这么写，就是 AI 味。

## 最该先改的三件事

按实测，一篇 2.1 万字的解读里最刺眼的不是用词，是版式惯性：

| 症状 | 实测 | 为什么是 AI 味 |
|---|---|---|
| 每张图下面四个加粗小标题一字不差地重复 | 14 组 ×4 | 人写十段图解不会十段都套同一个模板 |
| 破折号当万能连接词 | 44 处 | 中文破折号是重标点，一篇用三五个就够 |
| 加粗当装饰 | 85 处 | 加粗只用来标第一次出现的术语 |

前两条下面各有一节，第三条的规矩是：**只给首次出现的术语加粗，其余一律不加**。

## 图解不要套模板

四件事必须都做到（见 `figure-explain-spec.md`），但**不要把它们写成四个小标题**。
审计已经改成按功能检查：有没有交代坐标系、有没有说清哪个方向更好、有没有具体数字、
有没有划出这张图管不到的范围。顺序可以变，句子可以合并，语气应该随图而变。

❌ 模板腔（十张图都这样，就是 AI 味的主要来源）：

```markdown
**在回答什么问题**：作者要证明……
**怎么看这张图**：横轴是……
**能读出什么**：52% 对 4%……
**没能说明什么**：缺误差棒……
```

✅ 同样四件事，写成话：

```markdown
这张图要挡住一个质疑：动作性能的提升会不会全来自后训练。两个子图左边是人手数据、
右边是机器人数据，每行一个对手，横条从左到右是对手赢、平局、VPP2 赢，右端绿色越长
越好。对 Wan-2.1-14B，人手域是 52% 对 4%，机器人域拉到 96% 对 0%；
但换成最强的 Cosmos3-64B，就只剩 28% 对 18%。胜率是两两比出来的，不能跨行相加，
图里也没说评判者是人还是模型、每组比了多少对，平局占到一半以上，说明多数情况下
两边的差别肉眼难辨。
```

十张图之间要换写法：有的从质疑写起，有的从一个具体数字写起，有的先说这张图其实
没解决什么。

## 破折号

中文破折号的作用是插入和顿断，不是"连接两个想法"的通用胶水。模型爱用它，是因为
它能在不想清句子结构的情况下把两句话黏起来。预算：**每万字不超过 6 个**，一段里
不超过一个。

改法：
- 做解释的 → 改成冒号，或单独成句
- 做补充的 → 改成括号，或并进上一句
- 做转折的 → 用「但」「只是」「可惜」

❌ `事件级采样是真有消融支撑的——表 2 第五行直接把它关掉了——其余几条只能算声称`
✅ `事件级采样是真有消融支撑的：表 2 第五行直接把它关掉了。其余几条只能算声称。`

## 句式：把判断说出来，不要摆姿势

| 别写 | 改成 | 为什么 |
|---|---|---|
| 不是 X，而是 Y | 直接写 Y | 读者没说过 X，不需要先被否定 |
| 不仅…而且… | 挑有信息量的那一层写 | 两层通常是同一层 |
| 本质上 / 归根结底 / 真正的问题是 | 删掉，直接说那个问题 | 宣告深刻不等于深刻 |
| 值得注意的是 / 不难看出 / 由此可见 | 删掉 | 读者正在看，不需要被提示去看 |
| 让我们先看… | 直接看 | 不要起跑助跑 |
| 总而言之 / 综上所述 | 删掉整句 | 收束句一般只是重复上一段 |
| 需要说明的是 / 不可否认 | 删掉 | 没人提出异议 |

三连排比也要控制。等长的三项里第三项通常是为了凑齐才写的，砍掉它句子更干净。

## 词：说数字，不说程度

- 删掉 `极大地 / 大幅 / 充分 / 深刻 / 全面 / 显著 / 进一步`——有数字就写数字，
  没数字就承认没有
- 删掉 `赋能 / 助力 / 打造 / 彰显 / 加持 / 颠覆性 / 里程碑 / 强大的`——宣传稿词汇
- 删掉 `起到了关键作用 / 提供了有力支撑 / 奠定了基础 / 具有重要意义`——重要性由
  结果显示，不由形容词宣布
- `在一定程度上 / 某种意义上` 连用等于没判断；要么给边界条件，要么下判断
- `扮演了……的角色 / 充当了……` 一律换成「是」「有」

## 译文腔

论文解读最容易染上译文腔，因为底稿是英文。

- `进行分析 / 进行对比 / 进行验证` → `分析 / 对比 / 验证`
- `对于 X 而言，…` → `X 的…`
- `在……的情况下` → `如果…` 或直接换成具体条件
- `被……所……` → 主动句
- 一句里三个「的」就拆句
- `这张图展示了…` → 这是图注的活，解读要说作者拿它论证什么

## 节奏

长短句交替。连续五句都是三十字上下的陈述句，读起来就是模型的呼吸。
`check_tone.py` 用变异系数查这一项（段落和句子长度的标准差除以均值，低于 0.35 报警），
但它只能发现整齐，发现不了无聊——自己读一遍更准。

段落开头也要换。十四个段落以「在回答什」开头是硬伤。

## 姿势层：换了说法的同一个动作

`不是X而是Y` 查掉之后，同一个姿势会以三种变形回来。

**一、把两半调换。** 「是 A，不是 B」和「不是 B 而是 A」是同一句话。
「不过这是结构声明，不是实验」→「不过这只是结构声明」，后半句本来就由下一句承担。
同类：「要比的是上下两行，不是行内的时间演化」→「该比的是上下两行；行内从左到右只是时间推进」。

**二、自封重点。** 「掩码是整张图信息量最大、最该慢读的部分」「这是这条流水线上最该看的
一张图」「两条病因值得单独记住」—— 这是「起到了关键作用」换了件衣服。重要性由内容证明，
不由作者宣布。把那句删掉，直接写它为什么重要：「前面所有视频预测结果都来自多步采样的
模型，真正部署的却是蒸馏后的单步模型，这组图是两者之间唯一的桥」。
`关键在于` 也在这一类，和 `核心在于` 同病。

**三、设问自答。** 「动作训练会把泛化训掉，解药是什么？全文只有这张图给出了答案。」
设问开段是模型最爱的过渡，一篇文章里出现两三次是节奏，出现七次就是口癖。
预算是每万字 1.5 个。改法是把问句改成陈述：「引言里第二条病因是动作训练会把视频模型的
泛化训掉。这张图是全文对它给出的唯一一处直接解法。」

引用作者原话里的问句、以及论文自己列的研究问题，不算。

## 结构层：句子干净了，骨架还在出卖你

这一类最难自查，因为每个句子单独看都没问题。问题在文章的骨架上：它在报自己的做法，
或者把流水线内部的词摆到了读者面前。`check_tone.py` 的 `scaffolding` 项查四种。

**一、拿写法当标题。** `## 一、结论先行：这篇论文新在哪` —— 「结论先行」是写作手法的名字，
读者要的是这一节讲什么。改成 `## 一、新在哪里，证据有多硬`。同类：`实验：三个问题，三组证据`
这种对偶副标题，十二个标题全是「短语：卖点」一个模子时，把能直接用名字的那几节的副标题
去掉，`## 五、实验` 就够。标题里也不要带英文原标题，`（4. Experiments）`这种尾注把文章
变成双语目录，`no_english_tails` 会直接判 error。

**二、内部评级泄漏。** `innovations.json` 里的 `strength: strong|moderate|claimed`
是给流水线用的，不要变成表格的一列，也不要在正文写「强度分三级：有消融的记 strong……」。
给一篇论文的贡献在公开文章里逐条打三级分，是审稿表的动作，不是读者看的东西。

> ❌ `| 详细 caption 流程 | …… | 只有流程样例 | moderate |`
> ✅ `| 详细 caption 流程 | …… | 只有 图 2 的单个流程样例和整体系统对比，没有简短 vs 详细 caption 的消融 |`

判断照样要给，只是写成具体的话。最硬的那条顺带点明「全文唯一的单变量对照」，比标个
`strong` 有信息量得多。

**三、数清单。** 「创新点一共八条，先说最该记住的三条」「八条里只有一条算 strong」——
清点和分级都是审稿动作。说哪一条站得住、其余为什么站不住：「把变量隔离开的只有事件级
采样那一行，其余七处都是整条流水线一起上、一起测」。

**四、替自己交代写作规范。** 「下文每个数字后面都标了页码；百分比之间的差一律写百分点」——
照做就行，不用通知读者。同类：「接下来我们看」「如前所述」「本节将先……」。

判定方法和别处一样：一个研究员写完会不会专门加这一句？不会，他直接写下一句。

## 模板层：十张图走同一条路

最后一层，也是最难自己看出来的一层。四件事都做到了、加粗标签也删了，但十个图解
一律按「交代坐标系 → 哪个方向好 → 读出数字 → 划出边界」的顺序展开，读者读到第三张
就知道后面七张长什么样。`check_tone.py` 的 `template` 项统计这个顺序的分布，
同一个顺序占七成报警、占九成报错。

改法写在 `figure-explain-spec.md` 的「换入口」那张表里：这张图最值得说的是什么，
就从那里进。作者挑的成功样例，先说它只能当定性门槛；结论已经画在图上的，
先说判据是作者自己给的；数字差距极大的，先甩数字。

顺序散了之后不用担心漏掉哪件事 —— `audit_article.py` 的 `figure_explained` 照旧
按功能检查，它不关心顺序。

## 借来的权威

这一条是论文解读特有的，比别处都严重：你在替一篇论文说话，读者会把你写的每一句
当成论文里有的东西。

- `有研究表明 / 多项工作指出 / 业内人士认为 / 普遍认为` —— 解读里只能引**这篇论文**
  和它自己引用的工作。泛指的「有研究表明」等于凭空造了一篇参考文献。
- `论文没有说明这一部分，推测可能是……` —— 前半句是合格的批评，后半句把洞填上了。
  没写就写没写，停在那里：「论文没有交代评判者是人还是模型」。

❌ `论文没有给出训练成本，推测应该在数千卡时的量级`
✅ `论文没有给出训练成本，也没给卡数和训练时长，这项开销无从估算`

## 复述、术语和段内节奏

三条小一点的，都有预算或阈值。

**「也就是说」式复述。** 同一个判断说两遍，中间用 `也就是说 / 换句话说 / 简单来说 /
说白了 / 这意味着` 接上。预算每万字 2 个。真的需要把一句话翻译一遍，说明前一句没写好，
回去改前一句。

**术语漂移。** 同一个东西在一段里轮着叫「模型」「网络」「架构」「框架」。这是重复惩罚
推出来的，不是人的习惯 —— 解读里术语就是那个东西本身，该重复就重复。`check_tone.py`
的 `terms` 项统计一段内出现三个以上近义词的段落。

**段内节奏。** 全文的句长变异系数达标，不代表每一段都不平。一个段落里四句话长度都挤在
12 字以内，读起来就是匀速的。连续两句用「此外」「同时」「另外」开头同理，一段里这类
连接词一次就够。

## 机械残留

零判断、零误报，发布前必须清掉：

- 零宽字符与方向控制符（U+200B、U+FEFF、U+00AD、U+202A–U+202E）
- 引用脚手架：`:contentReference[oaicite:0]`、`citeturn0search0`、`【85†L261-269】`、`[cite: 2, 6]`
- 链接里的来源参数：`utm_source=chatgpt.com`、`referrer=grok.com`
- 没填的占位符：`[占位]`、`XX%`、`TODO`



有几类不要为了口吻去改：

- 术语、模型名、指标名：`流匹配`、`Cosmos3-64B`、`指令遵循成功率` 该重复就重复
- 表格里的短语：表格本来就要整齐，`check_tone.py` 不统计表格行
- 公式和代码块：原样保留
- 引号里的原文：引用作者的措辞时不要替作者改文风。`body_text()` 已经把 `>` 引用块和
  行内代码剔掉了 —— 把论文摘要译过来，里面带个「本质上」，那是作者的词，不是你的毛病
- 中文引号本身：`「」` 和 `“”` 保留，不要学英文工具把弯引号拉直
- 一段里五六个数字：图解按规范就要给数字加差值，数字密集是本分。别照搬评论性长文的
  数字密度上限

## 改法：重写段落，不要替换词

查出来的每一处都不要就地换同义词。模型味在句子结构里，不在单词里。
正确做法是把那一段的意思想清楚，用自己的话重写一遍，然后再跑一次 `check_tone.py`。

```bash
python3 scripts/check_tone.py <workdir>/article.md
```

有 error 必须改完；warning 要么改，要么在交付说明里讲清为什么保留。

## 外部来源

这份清单对照了 GitHub 上十余个去 AI 味 skill 和 Wikipedia 的 `Signs of AI writing`，
逐条筛过适不适用于中文论文解读。借了什么、以及哪两条故意没借，列在 `README.md`
的「口吻门禁的外部来源」一节。

最该记住的是其中一条告诫（出自 Humanizer-zh 的收尾）：**不要用自评分、字数下降或
「AI 味消失」代替事实与语义核对。** 这份规范只管口吻；数字对不对、页码对不对，
是 `audit_article.py` 和人的事。

# 逐图讲解规范

每张 figure 都必须做到四件事。表格和公式只有被选入核心清单的才做全，其余一句话带过。

**四件事是功能，不是小标题。** 不要把它们写成四个加粗标签——十张图十个同样的模板是
AI 味最大的来源，写法见 `chinese-voice.md`。`audit_article.py` 查的是功能：
有没有交代坐标系（`orientation`）、有没有说清哪个方向更好（`direction`）、
有没有至少两个数字（`reading`）、有没有划出这张图管不到的范围（`limits`）。
顺序随你，合并成一段也行。

## 三个强制输入（缺一不可）

| 输入 | 来源 | 作用 |
|---|---|---|
| caption 原文 | `source_bundle.json` → `evidence_inventory.figures[].caption` | 作者对这张图的官方描述 |
| 全部正文提及 | `source_bundle.json` → `mentions[]` 中 `id` 匹配的那条的 **每一个** `window` | 作者拿这张图论证什么 |
| 裁出来的 PNG | `screenshot-index.json` → `assets[].file`，**必须真的 Read 过** | 图里实际画了什么 |

第三条是本 skill 最容易退化的地方：只看 caption 写出来的讲解必然是复述。`audit_article.py` 的
`figure_viewed` 项检查 `crop_plan.json` 的 `verified_by` 是否已置为 `model-viewed`，这一项是 error 级。

`mentions[].window` 是按句切出来的，两类噪声要自己丢掉：

- window 内容基本等于 caption 本身（例如 `Figure 6` 的第一个 window）
- window 全是图内部的坐标轴刻度和图例文字（`0% 20% 40% ... Baseline wins Ties`）

丢完之后 `in_text_count` 若为 0，`fallback` 字段会是 `"section-body"`：此时回到
`outline[]` 里该 `pdf_page` 所属章节的正文去找作者的论证，不要凭图猜。

## 四件事

### 一、这张图在回答什么问题

落到作者的论证链上，指明它是为了支撑哪个主张、挡住哪个质疑才存在的。

- 禁止：描述画面（"这张图展示了三个柱状图"）
- 禁止：复述 caption 的名词短语
- 长度：1–2 句。可以从质疑写起，也可以从一个数字写起

### 二、怎么读这张图

把坐标系交给读者：横轴纵轴各是什么、分组/配色/子图编号 (a)(b) 各代表什么、
**哪个方向代表"更好"**。最后一条最常被漏掉，也最关键。

- 必须出现"越高越好/越低越好"或等价表述，审计按这个判 `direction`
- 子图多于一个时必须逐个点名
- 长度：2–4 句

### 三、读出了什么

具体数字 + 差值。规则：

- **差值一律写"百分点"，不写"%"**（52% 对 30%，差 22 个百分点）
- 数字要说清是从哪张图、哪张表读来的，写成文章里的「图 6」「表 2」。
  **不要写 `PDF p.7` 这种页码锚点** —— 读者手里没有那份 PDF，页码对他是死链，
  而图号表号在文章里就能翻回去。`numeric_anchors` 查的是数字附近有没有 `图 N` / `表 N`
- 原文的 `Figure 6` / `Table 2` / `Eq. 1` 一律写成中文的「图 6」「表 2」「式 1」，
  文章里的图号就是原文图号，不另行编号
- 只报能支撑第一件事那个主张的数字，不要把表里的数全抄一遍
- 至少两个数字，审计按这个判 `reading`
- 长度：3–6 句

### 四、这张图管不到什么

就地批判，**不单独成节**。从这几个角度挑真实存在的问题：

- 设置不同、不可直接合并的数字被并列
- 缺误差棒 / 缺 random seed / 单次运行
- baseline 口径不一致（参数量、训练数据、推理预算不可比）
- 样本量小（如 50 trials、25 episodes）
- 指标本身的局限（win rate 由谁评判、是否人工打分）

- 禁止：写"该图清晰有效地展示了……"这类无批判内容
- 禁止：把批判攒到文章末尾统一写
- 长度：2–4 句；确实没有可批判之处时，写明"这张图只是定性展示，不承担量化结论"
  之类的真实判断

四件事写成连续的一到三段，不要分成四个带小标题的块。十张图之间要换入口：
有的先说质疑，有的先甩数字，有的先说这张图其实没解决什么。

**换入口不是修辞建议，是被检查的。** `check_tone.py` 的 `template` 项统计十个图解
各自按什么顺序展开这四件事，同一个顺序占到七成就报警、九成报错。删掉加粗标签但十张图
照旧「交代坐标系 → 哪个方向好 → 读数 → 批判」一路走下来，读者照样看得出是批量生产的。

怎么换：这张图最值得说的是什么，就从那里进。

| 这张图的特点 | 从哪进 |
|---|---|
| 作者挑的成功样例、没有失败案例 | 先说这张图只能当定性门槛，再讲怎么读 |
| 结论已经画在图上（红绿圈、加粗行） | 先说判据是作者自己给的，读者无从核对 |
| 数字差距极大 | 先甩那个数字，坐标系随后补 |
| 图与正文表格数字不一致 | 先说这处矛盾 |
| 结构示意图，没有量 | 先说它只是结构声明、不承担量化结论 |
| 确实是干净的对照实验 | 按常规来：交代坐标系，再读数 |

一篇文章里前两列那种图通常不止一张，所以顺序自然就散了。如果十张图真的全是干净对照，
把其中几张的批判提到段首也不损失信息 —— 先知道一张图管不到什么，再去读它反而更省力。

## 退化反例

### 反例 1：图 6（胜率对比，两个子图 Human Hand / Robot）

❌ 退化写法（复述 caption）：

> 图 6 展示了预训练 VPP2 模型在视频预测任务上相对不同 baseline 的胜率。可以看到 VPP2
> 取得了领先的表现，证明了方法的有效性。

问题：第一件事降级成了 caption 翻译，没有论证链；没有坐标系说明；没有一个数字；没有批判。

✅ 合格写法：

> 作者得先证明预训练阶段的视频预测能力本身就超过了现有视频模型，否则后面的动作性能
> 提升完全可以被归因为后训练。两个子图，左边人手数据（Human Hand），右边机器人数据
> （Robot）；每一行一个对手，横条从左到右是 Baseline wins / Ties / VPP2 wins，右端
> 越长越好。对 Wan-2.1-14B，人手数据上 52% 对 4%，差 48 个百分点，机器人数据上拉到
> 96% 对 0%；但对最强的 Cosmos3-64B，人手数据只剩 28% 对 18%，领先 10 个
> 百分点。胜率是两两比出来的相对指标，不能跨行相加，图里也没交代评判者是
> 人还是模型、每组比了多少对样本，而平局占到 54%，说明相当多情况下两边的差别分不出来。

### 反例 2：图 1（三张柱状图 + 不稳定/稳定映射示意）

❌ 退化写法（描述画面）：

> 图 1 左边是大规模多样化操作数据，中间是 Video DiT 和 Action DiT 的结构，右边有三张
> 柱状图和两个对比示意，整体介绍了 VPP2 的框架。

问题：是画面清单，不是解释。读者读完不知道这张图想说服他什么。

✅ 合格写法要点：开头点明这张图同时干两件事，上半部分的三张柱状图是业绩单，下半部分
的示意图是全文论点（简单指令对应多个合理未来，详细 caption 把映射收成唯一）；中段给出
0.85 对 0.18、29.47 对 6.93 这类数字并指明它们出自图 1；末尾指出这三个维度是作者自己挑的，
而且没标误差范围。

### 反例 3：数字写法

❌ `VPP2 的胜率比 Cosmos3-64B 高 10%`（百分比之差必须写百分点）
✅ `图 6 里 VPP2 的胜率比 Cosmos3-64B 高 10 个百分点`

### 反例 4：模板腔

❌ 十张图都是这个骨架：

> **在回答什么问题**：…… **怎么看这张图**：…… **能读出什么**：…… **没能说明什么**：……

问题：四件事都做到了，但十段一个模样，读者立刻知道这是机器批量产的。审计已经不检查
这四个标签，别再写它们。

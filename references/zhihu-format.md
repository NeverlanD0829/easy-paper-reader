# 知乎排版规范

产出物是 `article.md` + `assets/`，但**知乎编辑器不认 Markdown**。把 `article.md`
整篇粘进去，`##`、`|---|`、`**` 和 `$x$` 会原样留在页面里当纯文本 —— 一篇文章里
十二个标题、二十行表格、五十处行内公式全部变成这样，就是所谓的「乱码」。

知乎编辑器是个 contenteditable，它不解析 Markdown，但**接受剪贴板里的富文本 HTML**。
所以发布前多一步 S9：

```bash
python3 scripts/to_zhihu_html.py <workdir>/article.md
```

在浏览器里打开生成的 `article-zhihu.html`，Cmd+A、Cmd+C，再到知乎编辑器里 Cmd+V。
标题、加粗、表格、公式、图片都会变成编辑器里的真实元素。

## 两种粘法的区别

| 能力 | 直接粘 `article.md` | 粘 S9 的 HTML |
|---|---|---|
| 标题 `##` / `###` | 显示成 `## 一、……` | 真标题（`####` 以下知乎没有，S9 一律压成两级） |
| 粗体 `**x**` | 显示成 `**x**` | 真粗体 |
| 行内公式 `$x$` | 显示成 `$x$` | 知乎自己的公式，可点开编辑 |
| 独立公式 `$$x$$` | 显示成 `$$x$$` | 居中的公式块 |
| 表格 `\|---\|` | 显示成一堆竖线 | 真表格，表头带底色 |
| 图片 `![]()` | 显示成 `![图 1：…](assets/…)` | 真图片，浏览器把位图一起放进剪贴板，知乎多数情况自动重新上传 |
| 引用块 `>` | 显示成 `>` | 左边一条竖线的灰字段 |
| 列表 | 多数情况能认出 | 真列表 |
| 脚注 | 不支持 | 不支持，引用来源就地写在括号里 |
| 目录锚点 | 不支持 | 不支持，不要写 `[跳转](#section)` |

公式之所以能过去，是因为知乎编辑器本身就把每条公式存成
`<img src="https://www.zhihu.com/equation?tex=...">`，S9 直接发这个 URL，粘过去的公式
和用公式按钮敲出来的没有区别。渲染由用户登录的浏览器去请求，本地不上传任何东西。

图片万一没自动上传，S9 的图注里会写明该手动传哪个文件。

## 公式

`article.md` 里公式一律写 LaTeX 文本，**不要自己渲染成图片**，交给 S9 转换：

- 核心公式用 `$$...$$` 独立成块，下面紧跟一句中文解释每个符号是什么
- 流匹配、扩散这类标准公式只提一句"这就是标准的 flow matching 目标"，不展开推导
- 面向泛 AI 技术读者：讲公式的**含义**，不讲推导过程
- `evidence_inventory.equations[].context` 是 PDF 抽出来的裸文本，带 `⌊⌋`、乱序片段和
  控制字符残留，**不能直接用**。按 `pdf_page` 和 `bbox_pt` 回到渲染页看一眼，自己重写 LaTeX

## 图片

引用形式固定：

```markdown
![图 6：预训练阶段的视频预测胜率对比](assets/figure-06.png)
```

- 路径用 `screenshot-index.json` 里的 `assets[].file`，原样不改
- alt 文本是**中文说明**，不是 caption 的翻译，要点出这张图的论证作用
- 编号用原文编号（图 6 / 表 2），方便读者对回论文
- 每张图紧跟四段讲解，见 `figure-explain-spec.md`

尺寸约束由 `crop_assets.py` 保证，无需手工处理：

| 限制 | 值 | 来源 |
|---|---|---|
| 宽度 | ≤ 1600 px | `screenshot-index.json` → `zhihu_limits.max_width_px` |
| 体积 | ≤ 5 MB | `zhihu_limits.max_bytes` |

超限时脚本会 LANCZOS 降采样，再超则转 JPEG，并把 `downscaled` 置 `true`。
`audit_article.py` 的 `zhihu_assets` 项（warning 级）复核这两条。

## 面向泛 AI 技术读者

读者懂深度学习基础，但不一定做机器人/具身智能。

**术语约定表**放在文章开头（创新点那一块之后、正文之前），只收录本文高频且领域专属的术语：

```markdown
| 术语 | 一句话解释 |
|---|---|
| VLA | 视觉-语言-动作模型，输入图像和指令、直接输出机器人动作的模型 |
| action chunk | 一次推理输出的一小段连续动作序列，而不是单步动作 |
| flow matching | 一种生成模型训练目标，学习从噪声到数据的速度场，可视作扩散的连续化变体 |
| end-effector | 末端执行器，机械臂最前端真正接触物体的夹爪或手 |
```

规则：

- 表格控制在 6–12 行，超过说明选词太宽
- **术语首次出现在正文时，仍要给一句话解释**，不能只靠表格
- 已经进入通用词汇的（Transformer、LoRA、zero-shot）不收录，首现时一句话带过即可
- 英文缩写首现写成「视觉-语言-动作模型（VLA）」，之后直接用 VLA
